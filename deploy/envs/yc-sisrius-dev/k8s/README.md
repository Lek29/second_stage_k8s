## Как задеплоить тестовый веб-сервер

1. Перейдите в корень проекта.
2. Примените манифест пода:
   `kubectl apply -f deploy/envs/yc-sirius-dev/k8s/test-pod.yaml`
3. Примените манифест сервиса:
   `kubectl apply -f deploy/envs/yc-sirius-dev/k8s/test-service.yaml`
4. Для проверки используйте Port Forwarding в Lens на сервис `test-nginx-service`.

## Сборка и публикация образов
Для деплоя приложения используется версионирование образов по хэшу `Git-коммита`. Это позволяет избежать конфликтов версий и обеспечивает возможность быстрого отката.

### 1. Подготовка окружения
Убедитесь, что вы авторизованы в Docker Hub:

```Bash

docker login
```
### 2. Сборка образа
Сборка производится из корня папки приложения. В качестве тега используется короткий хэш текущего коммита:

```Bash

# Узнаем хэш
$TAG = git rev-parse --short HEAD
# Собираем
docker build -t lekan29/django-app:$TAG ./backend_main_django
```

### 3. Публикация
Отправьте собранный образ в удаленный репозиторий:

```Bash

docker push username/django-app:$TAG
```

## Эксплуатация Django-приложения в Kubernetes
Краткое руководство по тому, как устроено приложение и что делать в типичных ситуациях.

### 1. Что нужно сайту для работы
* **База данных:** PostgreSQL. Подключение идет через порт `6432` с обязательным использованием SSL.

* **Секреты:** Все доступы к базе лежат в секрете postgres-db-urls в формате `DATABASE_URL`.

* **Сертификаты:** Для безопасного соединения с БД используется сертификат root.crt, который монтируется из секрета postgres-ca-cert.

### 2. Настройки через переменные окружения
Все основные параметры прописаны в манифесте django-app.yaml в блоке env:

* `DATABASE_URL`: Полная строка подключения (логин, пароль, хост). Берется из секретов.

* `SECRET_KEY`: Секретный ключ для механизмов защиты Django.

* `ALLOWED_HOSTS`: Список доменов (наш URL), по которым Django разрешает к себе обращаться. Без этого будет ошибка 400.

* `DEBUG`: Режим отладки. На проде должен быть False.

### 3. Инструкции по обслуживанию
**Как выкатить новую версию (Update)**

1. Собери новый образ и запушь его в Docker Hub: docker push username/image:tag.

2. В файле `deploy/envs/yc-sirius-dev/k8s/django-app.yaml` обнови значение `image:`.

3. Примени изменения:

```Bash

kubectl apply -f deploy/envs/yc-sirius-dev/k8s/django-app.yaml
```

### Как проверить результат?
В Lens в разделе **Pods** старый под должен плавно замениться на новый (статус Running и 1/1 Ready). Если новый под падает в CrashLoopBackOff, значит в коде или настройках ошибка.

### Работа со скриптами
Если нужно обновить базу или создать админа, заходим в терминал пода (в Lens кнопка >_) и выполняем:

* **Миграции:** `python manage.py migrate` (делать после каждого обновления кода, если менялись модели).

* **Админка:** `python manage.py createsuperuser` (создание учетки для /admin).

### Где искать ошибки (Debugging)
Если сайт не открывается, первым делом смотрим логи пода:

1. В Lens нажимаем на нужный Pod.

2. Справа сверху иконка Logs.

3. Весь путь ошибки (Traceback) будет там. Основные проблемы обычно в конце лога.
